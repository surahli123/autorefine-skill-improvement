## Problem Statement

skill-improver is a working 3-file meta-skill but has no name, no distribution plan, and no README. Teammates can't discover or install it. The public can't find it. The methodology (Karpathy autoresearch + Hamel Three Gulfs + v2.0 design audit) is valuable but invisible.

## Demand Evidence

- User built this to solve their own pain: manually running autoresearch on ds-review and ds-trace was effective but not repeatable or shareable
- Two successful applications: ds-review (85.7% → 100%), ds-trace (60% → 100%)
- In-house coding agent team is actively building skills — immediate internal audience
- Koylan's similar repo (context engineering skills) got 14.1K GitHub stars — market appetite exists

## Target User & Narrowest Wedge

**Internal:** DS/ML engineers on user's team who build Claude Code skills for their in-house agent. They need a structured way to measure and improve skill quality.

**Public:** Claude Code power users who build their own skills and want a systematic improvement methodology. Self-serve via GitHub.

## Constraints

- Must work on in-house coding agent (~late 2025 Claude Code: Read/Write/Bash, limited specialized agents, no auto-triggering)
- 3-file core architecture (SKILL.md + dashboard.html + references.md). Repo will also contain README.md and optionally example results.
- Hamel's evals-skills are optional enhancement, not required
- README must be concise (in-house agent context budget)

## Premises

1. Teammates already build skills and would see immediate value ✅
2. Public version should be a real installable tool, not just a learning artifact ✅
3. In-house agent CAN read READMEs — just less efficiently than Claude Code ✅

## The Name: `/autorefine`

**Decision:** `/autorefine`
- "auto-" prefix signals Karpathy autoresearch lineage
- "refine" is the action verb — iterative improvement, not generation
- 10 characters — clean as a slash command
- Rename checklist:
  - `skill-improver/` → `autorefine/` (folder name)
  - SKILL.md frontmatter: `name: skill-improver` → `name: autorefine`
  - SKILL.md Quick Start: `/skill-improver` → `/autorefine`
  - Deploy path: `~/.claude/skills/skill-improver/` → `~/.claude/skills/autorefine/`
  - Handover doc references
  - Memory files referencing old name
  - Note: `autoresearch-<skill>/` workspace naming stays — it describes the methodology, not the tool

**Rejected alternatives:**
- `/autoresearch` — too presumptuous to claim Karpathy's exact name
- `/autoskill` — sounds like auto-generate, not auto-improve
- `/autohone` — "hone" doesn't translate well for non-native speakers
- `/autoresearch-skills` — 20 chars, misleading ("researches skills" vs "improves skills")

## Distribution Strategy

### Internal (Primary)
- **Repo:** Internal git repo that teammates clone to `~/.claude/skills/autorefine/`
- **Confluence page/blog:** Detailed write-up with methodology explanation, use cases, and results. Serves as the canonical internal reference — searchable, linkable, persists beyond Slack.
- **Slack:** Announcement in team channel with dashboard screenshot + link to Confluence page + install instructions
- **Recorded demo:** Short walkthrough video showing a real Phase 1-3 run. Teammates can watch async without needing a live session.
- Dashboard (Karpathy step graph) is the show-don't-tell artifact embedded in both Confluence and the demo

### Public (Secondary)
- **GitHub repo:** `github.com/<user>/autorefine` — clean, installable, standard Anthropic Skills format
- **Discovery:** X/Twitter posts linking to the repo. Reply to Karpathy/autoresearch threads with the use case ("We applied autoresearch to Claude Code skills — here's what happened")
- **README IS the story:** No separate blog. The README tells the journey: problem → methodology → results (60% → 100%) → how to install → how to use
- **Social proof:** Dashboard screenshots in README showing the Karpathy step graph with real improvement data

### README Structure (to be written)
1. **One-line pitch:** "Karpathy's autoresearch + Hamel's Three Gulfs, applied to Claude Code skills"
2. **Dashboard screenshot:** The Karpathy step graph showing a real improvement staircase
3. **The story:** "We improved ds-trace from 60% → 100% in 3 experiments" (concrete, not abstract). *Dependency: requires completed ds-trace results from parallel session.*
4. **Install:** `git clone` + copy to `~/.claude/skills/autorefine/`
5. **Usage:** `/autorefine path/to/your-skill/`
6. **What it does:** Pipeline overview (Gulf 1 → Gulf 2 → Gulf 3)
7. **Requirements:** Claude Code (or compatible agent). Optional: Hamel's evals-skills.
